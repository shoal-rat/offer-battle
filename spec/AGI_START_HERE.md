# 从这里开始：把《秋招斗兽棋》一次做成可玩的游戏

目标版本：2.0.0。项目名称：秋招斗兽棋：Offer 开打。默认工作方式：直接实施、生成资源、执行测试、修复问题、启动项目、交付运行证据。

用户已经定下核心方向：把秋招比Offer具象化；角色是可爱的成年二次元职场小人；台词要有攻击性与戏谑感；第一学历和第二学历组合；海外有Top 50、Top 100、100+；校友流派拥有校友主角大招与专属抽象演出。

## 1. 交付物

交付一个完整网页游戏工程。玩家可以录入Offer、选择双学历、生成角色、挑三张Offer、选牌、与机器人或朋友开打一整局、看战报、再来一局。

根目录提供 `start.sh`、`start.ps1`、`README.md`、`.env.example`、依赖锁文件。正常开发入口为 `npm run dev`；一键入口负责检查环境、安装锁定依赖、生成必需本地资源、启动服务。所有安装和生成步骤必须返回真实状态。

默认无需任何模型密钥。附带可直接使用的本地角色、台词与示例Offer。提供密钥后可以生成新的个人卡面。对局裁定始终使用确定性规则。

## 2. 阅读顺序与唯一事实源

先读 `game_design.md`，再读 `rules_catalog.json` 与 `education_catalog.json`。随后阅读工程规格、状态机、美术规范、资源清单和测试用例。

战斗数值以两个JSON目录为准。时序与交互以本设计书、`engineering/state_and_network.md` 为准。资源交付按 `art/asset_manifest.json`。本文件定义交付流程。

相同规则发现冲突时，先定位唯一事实源，更新描述与对应测试，记录到 `DECISIONS.md`。缺少工程细节时选依赖更少、容易启动的实现，记录决定后继续。已经确定的玩法数值不自行调整。

## 3. 需要完整实现的玩法

三十点心态，逐轮一至八小时，每人四个场上位置，三张公开Offer，十五张通用牌库，十二轮上限。三十张通用牌、十一个Offer模板、七种条款都可用。

学历包含十个主技能与十一个进修技能。进修第四轮解锁，每局一次。主技能与进修每个自己的回合共用一次机会。110种有序搭配全部合法。

校友流派：两次各花2小时的校友集合，各恢复1心态。第三次花2小时给己方Offer＋4排面／＋4底气上限。大招每局一次，此后技能为2小时恢复2心态。第二学历校友流派为3小时给己方Offer＋2／＋2。本硕双校友流派只有表现层联动，不添加第三技能。

保留谈薪、年龄轨道、三十五岁通知、转管理、三个话题、隐藏反话、收回保龄、Offer退场损失、焦虑。所有时间折扣最低支付1小时。

## 4. 实施顺序

先建立项目结构、规则类型、目录加载与单测入口。实现规则纯函数，跑通自动对局。再接服务端、网页牌桌、机器人、好友房和回放。

随后按资源清单生成统一美术。接入Offer录入和创作队列，补全首页、收藏、双学历配队、教程、战报与分享。最后进行双浏览器完整对局、手机端截图、资源完整性和构建检查。

每个阶段都在当前开发任务内继续执行。开发记录写到 `IMPLEMENTATION_STATUS.md`，不要用“等用户确认”替代已经定义的实现。

## 5. 首发工程选择

采用TypeScript统一规则、服务器与客户端类型。前端采用React、Vite、CSS和SVG。Node 24 LTS作为默认运行主版本，具体依赖采用当前可安装且相互兼容的精确版本，提交锁文件。

牌桌使用DOM卡牌，短动画使用CSS或Web Animations。服务端使用单个Node进程，HTTP加WebSocket。首发文件存储使用原子写入与事件日志，默认无需数据库服务、对象存储或消息队列。

客户端按资源ID读取素材映射。音效在首次用户操作后启用。网络与绘图接口失败时，现有牌组和本地练习持续可用。

具体目录、脚本、接口、断线和资源模式见工程文档。工程选择可因环境调整，改变必须保留同等交付行为。

## 6. 美术完成标准

角色是精致可爱的二次元小人，有男有女，约2.5至3头身。职业道具和表情要能识别。清晰卡框、学校章、第二学历配饰、牌背、棋盘、音效全部连接到实际界面。

存在绘图工具时按 `prompts/art_generation.md` 与资源清单使用/image gen工具批量生成。

人物与准确文字分层。中文规则、排面、底气、年龄、Logo由UI绘制。禁止把整张卡生成成一张难以修改的位图。禁止为110种双学历组合分别生成110份完整主角；使用10张主角母版与11组毕业配饰合成。

每项输出登记到 `assets/production_report.json`，包括实际文件、模式、大小、尺寸、校验和与关联资源ID。资源示意描述无法替代实际素材。

## 7. 验收门槛

必须实际执行并通过：类型检查、规则单测、生产构建、资源路径检查、零密钥启动、机器人整局、两个浏览器上下文好友对局、重连、手机操作截图。

必须覆盖双学历共享机会、第二学历第四轮解锁、校友流派大招次数、双校友流派累计强化、回手清强化、年龄保留、技能伤害不触发合同、单目标技能不误触挡话、返场与谈薪降费。

测试机器人不能读取对手秘密。测试报告保留命令和退出码。未通过项列出具体错误与已完成部分，不把待办写成通过。

至少输出首页、Offer生成、双学历配队、满场战斗、校友流派大招、结算六类截图；手机和桌面都需要走查。资产验收独立打开角色图、卡框、特效与声音。
