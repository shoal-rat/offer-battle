# 2.2 发布准备与能力边界

本文对应 2.2.0-beta.2 公测源码，说明当前实现和发布顺序；独立验收与补丁在上线后持续进行。已发布版本、实际地址和公网验收由 [DEPLOYMENT.md](../DEPLOYMENT.md) 维护。战斗规则仍为 2.0.0，Offer 编译器仍为 2.1.0，机器人策略独立记录为 2.2.0；发布元数据以实际提交和构建产物为准。

## 这一版改变什么

纸片场景把制作、收藏、配队和邀请放进同一个可点击空间；文字、按钮与装饰分离。自定义卡沿用可核查的固定公式，增加从空草稿、字段确认、资料修订到生成任务的可靠流程。旧任务不覆盖新草稿，已开局的卡牌定义不随收藏编辑而变化。

四档机器人难度与三种风格、完整或快速开局分别配置。邀请可跨越登录流程，本地收藏迁移先展示预览并保留原件。战斗支持默认点击或拖牌即用、有目标的出牌纸飞机与可选放大读牌；保留公开信息提示、事件关联的复盘和可关闭的情境提示。纸飞机提交前可取消，场上角色攻击直接冲撞，实际费用与伤害仍由权威指令结果决定。“慢慢练习”从准备到重赛都不限时，普通计时局与好友保持期限。统一动效调度支持取消、减少动态和后台清理。

beta.2 将实体攻击放慢至 1,180 ms，退场保持 460 ms 占位，并避免原地分身；队列压缩/追帧阈值调整为 3,000/5,000 ms，终局设计预算 1,830 ms、上限 2,000 ms。此变更覆盖早期升级包的确认层数与动画时序；具体验收映射见 [补充说明](QA_BETA_2.md)，不修改旧测试的实际结果。

## 能力由哪一端提供

| 能力 | 静态游客 | Cloudflare 账号 | Node 自托管 |
| --- | --- | --- | --- |
| 人机、教程、当前回放 | 本地规则与独立 Worker | 登录不替换当前本地对局 | 本地服务与独立线程 |
| 自定义收藏 | 当前浏览器保存 | 可主动迁移与同步 | 服务数据目录 |
| 好友房与长期战报 | 需要注册或登录 | Worker / Durable Objects 权威裁定 | Node 服务裁定 |
| 本地角色与文案 | 内置能力 | 内置能力 | 内置能力 |
| 远程文字、绘图、图片字段提取 | 不把未配置服务显示为可用 | 当前接口能力默认关闭 | 配置相应适配器后可用 |
| 独立实验 | 玩家主动开启后按本地能力提供 | 还须后端能力开关允许 | 按服务端能力提供 |

每个客户端读取 `/api/capabilities` 决定可用入口。Cloudflare 的 `ENABLE_BEST_OF_THREE` **未配置或不等于字符串 `true` 时关闭**。当前配置未打开它；也未配置云端远程绘图、文案、提取或配音能力。前端开关不授予服务端能力。

挑战、Boss、系列赛和节奏模拟不改写默认标准玩法。云端保存普通本地战绩时拒绝带实验构造的记录；实验战报不能作为标准战绩导入。系列赛每局使用正常规则，局间只更换应对牌，成就仅提供外观奖励。启用新实验需另外运行相应测试并记录能力变更。

## 验收顺序

1. 在开发分支完成基础类型检查、规则和传输回归、素材检查及生产构建；失败样本与尚未复核项保留在报告中。
2. beta.2 先对固定候选构建亲自完成一套真实游玩流程，修复发现的体验问题；随后将可审查实现提交 GitHub，记录提交哈希，部署兼容后端和对应 Pages 网页并检查正式网址。
3. 针对已发布提交启动独立测试代理验收，保留场景、设备、观察结果和证据。
4. 发现问题后提交并发布小范围修复，重新检查受影响路径；失败和未完成验收保留在报告中。

1,000 局机器人基准已有实际报告；48 次独立产品运行另行统计，两者不能相互替代。实际数量、失败、超时和中断以 [验收状态](../reports/upgrade-v2.2/acceptance.json)、[AI 报告](../reports/AI_IMPLEMENTATION.md) 及其关联数据为准。Motion 的正常连续对局测量与未达标压力样本见 [专项报告](../reports/MOTION_2_2.md)。

## 兼容部署顺序：先 Worker，再 Pages

新网页依赖草稿修订、保存幂等、邀请、迁移和能力查询等新协议；不能只替换网页后让它连接旧后端。

1. **准备并验证后端。** 保留现有账号和房间 Durable Object 类名、绑定与迁移历史，不删除线上存储。不把开发用数据复制到生产。复核 `ALLOWED_ORIGINS` 是实际网页的来源，不包含路径。运行 `npm run typecheck:cloudflare`、`npm run test:cloudflare`，再由维护者执行 `npm run deploy:cloudflare`。
2. **验证兼容性。** 检查线上 `/healthz`、`/api/capabilities`，确认新增实验仍为关闭；检查旧收藏、旧回放与进行中的旧房间。用隔离账号验证注册、登录、创建与加入好友房、WSS、重连及保存。无需为升级强制退出所有玩家或清空数据。
3. **构建静态网页。** 设置真实 HTTPS 后端，不在 URL 中附带令牌或密钥。脚本固定 `/offer-battle/` 和静态游客模式，并生成 `release.json`：

   ```sh
   VITE_API_BASE_URL=https://your-worker.example.workers.dev npm run build:pages
   ```

4. **验收待发布产物。** 使用生产产物预览进行静态浏览器回归，确认子目录资源、访客断网人机、邀请登录返回、账号保存和好友恢复。生产包不启用 sourcemap；本地验证不能替代正式 HTTPS/WSS 检查。

   ```sh
   npx vite preview --outDir dist-pages --base /offer-battle/ --host 127.0.0.1 --port 5197
   # 在另一个终端运行：
   STATIC_TEST_URL=http://127.0.0.1:5197/offer-battle/ npm run test:e2e:static
   ```

5. **发布 Pages 子目录。** 在网站仓库的干净工作区运行 `npm run prepare:pages -- /path/to/shoal-rat.github.io`。该脚本校验目标仓库与已有发布标记，只准备 `offer-battle/` 的文件，不自动提交或推送。审查差异后发布，保留网站其他内容。
6. **核对正式版本。** 正式网址的 `release.json`、资源和 API 必须指向同一批发布记录。验证真实双客户端对局、重连、结算、保存和手机可读性，把时间、提交及脱敏结果补入部署记录。

发生网页回归时，可回退到此前验证过的 Pages 产物，同时保留兼容后端。后端回退必须先评估新保存数据和房间协议，不能直接删除迁移或回滚持久化数据。暂时关闭实验能力应使用对应能力开关，并明确在途系列赛如何结束；不靠前端隐藏入口假装服务已停止。

## 尚不能从现有结果推导的结论

- 40 项动作已建立运行映射，不等于每一项均有独立、逐帧的视觉验收。
- 桌面 Chromium 实验室录像与帧间隔不等于低端手机实机性能。
- 正常速度连续对局已测，频繁重建整张牌桌的压力样本仍有超预算帧，不能写成整体性能全部通过。
- 旧线上一次结算面板未出现的问题在取证复跑中未复现，尚不能归因于某个传输缺陷；2.2 对演出增加独立收尾上限，仍需正式版本复核。
- 战术回归和合法观测证明的是相应局面，不代表机器人达到目标胜率、没有任何漏斩或已证明真人平衡。

基础结果与历史回归分别保存在 [TEST_REPORT.md](../TEST_REPORT.md)，功能边界见 [IMPLEMENTATION_STATUS.md](../IMPLEMENTATION_STATUS.md)。
